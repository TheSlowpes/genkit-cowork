# Domain docs

This repo has one domain context. Before exploring, read the root `GLOSSARY.md`
and any relevant decisions in `docs/adr/`. If either is absent, proceed silently.
`/domain-modeling` creates them when there is a term or decision to record.

Use glossary terms in issues, specs, code, and tests. If a proposal contradicts
an ADR, name the ADR and explain why it should be reopened.
